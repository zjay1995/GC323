# Bugs - 2.5.0

Released: not yet - `VERSION` is set to 2.5.0 and this is the list it
will ship with.
Products: gc323 2.5.0, gc301 2.5.0 (m30 0.1.0 is not shippable, see
`config/m30.h`)

## Fixed

| Issue | Severity | Models | Summary |
| ----- | -------- | ------ | ------- |
| - | **critical** | all | The oven never heated. `Acquire::EnableOven()` opened with `if(AcquireRUNNING=1) return;` - an assignment, not a comparison - so it always returned before closing the oven enable relay, and `oven_enabled` never became TRUE. `SetOvenTemperature()` pulsed its output into a contact that was never enabled. |
| - | major | all | Use-after-free in the temperature controller. `delete tempcontrol` in `Acquire::Continue()` (TRANS_METH) did not clear the pointer, and TRANS_METH is re-entered per point and per calibration. A ramped method followed by an isothermal one on the same acquisition left `Continue()` calling `ControlTemperature()` on freed memory every idle tick, and the destructor then deleted it a second time. |
| - | minor | all | The About box showed a version that was typed into `ABOUT.CPP` by hand, so it could disagree with what was built. It now shows the model and the version the build actually used. |
| - | minor | all | The About box showed no model, so the only way to tell a GC323 build from a GC301 build was to read the source. It now shows `MODEL_CODE`. |
| - | minor | all | Copyright line still read 1999-2019. |

No entries have issue numbers because there was no issue tracker when
they were found. From 2.5.1 on, every line here has one - see
[README.md](README.md).

## Known open

| Issue | Severity | Models | Summary | Workaround |
| ----- | -------- | ------ | ------- | ---------- |
| - | major | m30 | `config/m30.h` is a stub. Every switch below the model-family block was copied from the GC323 and none has been checked against an M30. | Do not ship an M30 build. |
| - | major | gc301 | `config/gc301.h` was reconstructed from the GC323 config plus the model-family flags. `POINTS()` and `OVEN_EQ_INJ()` in particular are known to have differed on the 301B/301c. | Diff it against the `INTERNAL.H` in the last 301 folder before building a 301 for a customer. |
| - | cosmetic | all | The Communication Agent (`WPEAKC`, a separate small project in `src/`) still has its own About box hard-coded in `WPEAKC.RC`: "Version 2.1 ... 1999-2001". It is a static `CTEXT` in the resource, not driven by `ABOUT.CPP`, and it is not one of the three products in `VERSION`. Left as it was rather than invent a version for it. | - |
| - | major | all | The autozero hold went from 3 s to 10 s. A valve gets an autozero window when it opens and another when it closes; if the valve is open for less than the hold, the first window's AutoZero(FALSE) now lands after the second window has started and cuts it short. At 3 s this needed an X1 open time under 3 s. Check the X1 and X2 open times in every method in use. | Keep X1 and X2 open for at least 10 s, or lower `AUTOZERO_HOLD_MS` in `src/ACQUIRE.CPP`. |
| - | minor | gc323 | X3's autozero windows were left at their 2021 values (1 s delay, 6 s hold) rather than following X1 and X2 to 10 s, because they were set differently on purpose. | - |
| - | minor | all | Apart from the two fixes above, no functional code changed in 2.5.0, so any other defect present in 2.4.44 is still present. There is no per-issue record of what those are; 2.4.44 and earlier were released without one. | - |

## Notes

2.5.0 is a minor bump with no functional change. It marks the point where
builds became reproducible: the version and the model settings come from
`VERSION` and `config/`, both committed, so `git checkout v2.5.0` plus
`tools\build.bat gc323` reproduces the shipped EXE. A 2.4.x EXE cannot be
reproduced - the settings it was built from only ever existed in one
person's working copy of `INTERNAL.H`.

Before shipping: build gc323 and gc301, and confirm the About box reads
the right model and `2.5.0` on each.
